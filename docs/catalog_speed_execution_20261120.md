# Catalog execution speed changes, 2026-11-20

## Rollback checkpoint

Previous deployed/code revision: `d64f28a2fc9238480caeab573d66e761007b3feb`.
The annotated tag `rollback/catalog-before-speed-20261120` was pushed before edits.
Render can redeploy that revision without resetting a developer's checkout.
For an execution-only rollback on the new revision, set
`CATALOG_PERFORMANCE_ENABLED=false` and restart/redeploy. This selects the retained
serial executor, bypasses reference-map caching, and restores PNG compression 6.

## Changes

- First shot completes before speculative work starts. Thereafter a maximum of
  two ready jobs run, respecting declared dependencies and failed anchors.
- Uploaded request files are snapshotted once and each job gets independent
  BytesIO streams and options. Identity/reference assignment still goes through
  the original garment-owned config and runner privacy guards.
- Heavy local composites and finishing share a one-job processing gate, limiting
  peak memory on the existing free Render instance. No service plan was changed.
- A separate single upload worker overlaps upload with the next generation.
  Dependencies use local generated bytes rather than waiting for uploaded URLs.
- Delivery and final image order remain the declared panel order. Cancellation
  cancels queued jobs and waits for already-started work before releasing the
  catalog slot. A first-shot quota rejection does not launch speculative calls.
- Original-RGB palette/body-region analysis is cached inside one immutable-source
  request only. Different inputs, crops and palette parameters have separate keys;
  caller mutation cannot contaminate another shot's palette.
- Static reference luminance, masks and relief maps have a byte-bounded 32 MiB
  process cache, keyed by complete file paths, mtime and size. Uploaded fabrics
  never enter this global cache.
- Catalog PNGs use compression level 3, keeping original dimensions and decoded
  pixels. This covers collage, composites, derived crops and blazer finish output.
  No garment prompts, references or AI output resolutions were reduced.

Settings: `CATALOG_GENERATION_WORKERS=1|2` (default 2),
`CATALOG_PNG_COMPRESS_LEVEL=0..9` (default 3), and the rollback flag above.

## Verification

The full 205-test suite passed with the new scheduler enabled. Dedicated tests
cover two concurrent jobs, non-shared stream cursors, front dependencies, upload
overlap, ordered delivery, cancellation, first-call quota, request cache isolation,
pixel equality and selecting the old executor with the rollback flag. Existing
serial-order prompt-routing tests explicitly use one worker; separate concurrency
and provider-boundary tests exercise the two-worker path.

Pixel comparisons cover multiple plain colours and a patterned swatch, reference
maps with and without cache, and collage encoding. These verify decoded pixels,
not identical compressed file bytes. Changing compression can increase upload size.

Timing logs now include one `catalog_total` stage with garment/style/catalog ID.
Do not add per-shot stage durations to estimate elapsed time on the parallel path:
jobs and uploads overlap, and local-job durations can include waiting for the
processing gate. Compare `catalog_total` and client request duration separately.

The existing baseline logs are approximately business 87.3s, casual 85.2s, wedding
67.3s and Pathani 78.7s. These are historical observations, not guaranteed new
results. Live speed verification requires explicit paid-generation authorization;
no lower-latency claim follows from local mock-provider test timings.

## Saved-output replay

`tools/benchmark_catalog_pipeline.py` replays previously saved AI responses through
the actual old/new finishing and composition code, using mock storage only. On the
business report `2026-11-20_135431_001`, the local desktop runs were 14.892s old and
12.948s new. All six finished images AND the final collage had identical decoded
pixels. Three AI responses were replayed and seven mock uploads made per run;
no external requests were sent. Evidence: `tmp/catalog_speed_business_replay.json`.
This validates output equivalence and local processing, not deployed latency or
the network-overlap speedup. A patterned-swatch comparison also passed after the
full suite, along with all six dedicated performance tests.
