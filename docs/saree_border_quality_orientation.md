## Review of the proposed changes

| Proposal | Assessment |
|---|---|
| Detection thumbnail 512×640 → 768×960 | Retained for finer position sampling; no evidence of “50% greater accuracy”. The thumbnail only estimates coordinates; it does not set final source-pixel resolution. |
| Desired band width .46 → .65 | Retained as a larger display choice. About 41% more requested display width is not a measured 40% sharpness improvement. |
| Upscale every native strip below 80px to 80px | Removed. Adds no photographed detail, introduces interpolation and hides the original source scale from later enlargement limits. Not pixelation-proof. |
| LANCZOS in `Image.transform(... AFFINE ...)` | Invalid. Reproduced ValueError with the installed Pillow. Restored supported BICUBIC for transforms; LANCZOS is used only with supported resize operations. Syntax parsing cannot detect this runtime error. |

Primary reference: [Pillow Image.transform](https://pillow.readthedocs.io/en/stable/reference/Image.html#PIL.Image.Image.transform)
documents NEAREST/BILINEAR/BICUBIC for geometric transforms. A higher detection
resolution, wider display or interpolation filter cannot reconstruct source
details absent from a photographed narrow band.

## Implemented corrections

1. Compose rectification and diagonal placement into one inverse projective
   mapping. Final colour pixels are sampled directly from the original source
   once, not from an enlarged intermediate strip. The intermediate native strip
   is still available for inspection/fallback; its interpolated pixels do not
   supply the production detail image when a source quad is available.
2. Keep original native width/height in diagnostics. Do not artificially upscale
   to 80px before selecting the visible segment. Report actual display scale.
3. Reject line pairs whose width nearly collapses or changes by more than 2.5×
   over the sampled segment, preventing a narrow wedge becoming stretched blur.
4. Handle coloured edge-touching trims separately using body/edge colour contrast.
   The new pink-source quad selects the actual gold band at the image edge.
5. Normalize a right-side band by 180° so its outer edge is presented on the left.
   This is a presentation convention, not semantic recognition of every motif.
   `options.fabric_border_rotation` accepts `auto` (default), `0`, or `180` for
   fabric-specific correction. Other garments and the normal endpoint reject it.
6. Public catalog UI and Desktop tester have an optional orientation selector.
   Tester update is reproducible with `scripts/update_tester_border_orientation.py`;
   external files were backed up under ignored `tmp/tester_border_orientation_backup`.
   Refresh the tester page to load the control.

Only the Saree fifth-panel renderer changes visually. Its side-view reference
context helper, first/front, rear identity prohibition, product photo, front-derived
pleats and 3:4 layout remain intact. No new model or package dependency was added.
